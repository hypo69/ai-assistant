## 🔎 Обзор лончера

Скрипт `assist.ps1` — единая точка входа для управления локальным микросервисом **AI Assistant**:
- **Умное окружение:** автоматическая проверка и активация виртуального окружения Python (`venv\Scripts\Activate.ps1`).
- **Стек Paperless-ngx:** проверка доступности демона Docker Desktop и опциональный запуск/мониторинг контейнеров Paperless.
- **Поддержка нескольких UI-движков:** бесшовный запуск приложения в Electron, WebView2 или стандартном браузере.
- **Контроль конфликтов портов:** умное переподключение к активному серверу или «горячий» перезапуск с освобождением сокета.
- **CLI-утилиты:** полнофункциональный инструментарий для индексации коммитов, проверки RAG и запросов к LLM без запуска веб-интерфейса.

## ⚡ Шпаргалка быстрого старта

```powershell
# Канонический запуск по умолчанию: безопасное подключение и открытие Electron
.\assist.ps1 -c --engine electron

# Быстрый запуск (автоматически эквивалентен .\assist.ps1 -c --engine electron)
.\assist.ps1

# Запуск интерфейса в Electron без открытия отдельного окна логов Paperless
.\assist.ps1 -NoPaperless

# Открыть интерфейс в обычном системном браузере
.\assist.ps1 -c --engine browser

# Запустить только REST API бэкенд в консоли (без открытия окон)
.\assist.ps1 --no-gui

# ВНИМАНИЕ: Перезапуск сервера с принудительным убийством процесса на порту
# (Использовать ТОЛЬКО с предварительного явного подтверждения пользователя!)
.\assist.ps1 -r

# Посмотреть статус Git, Wiki и базы чанков RAG
.\assist.ps1 status

# Задать естественный вопрос по истории изменений проекта
.\assist.ps1 query "Когда исправлялась ошибка запуска телеметрии?"

# Проиндексировать последние 30 коммитов в векторную базу
.\assist.ps1 index --limit 30
```

Если подкоманда не передана, `assist.ps1` автоматически запускает подсистему `serve` (поднимает FastAPI бэкенд и открывает графическое окно).

## 🎛️ Параметры лончера PowerShell

Эти параметры перехватываются и обрабатываются на уровне самого PowerShell-скрипта до передачи управления Python-модулю:

| Параметр | Алиас | Описание |
|---|---|---|
| `-NoPaperless` | `--no-paperless` | Отключает автоматический запуск отдельного окна PowerShell со стримингом логов контейнеров Paperless-ngx. Рекомендуется использовать, если Docker-контейнеры уже запущены в фоне. |

> [!NOTE]
> Для чисто консольных подкоманд (`status`, `query`, `commits`, `index`, `--help`) консоль Paperless пропускается автоматически без необходимости указывать флаг `-NoPaperless`.

## 🖥️ Движки графического интерфейса (`--engine`)

AI Assistant поддерживает 4 режима отображения интерфейса:

```powershell
.\assist.ps1 --engine <electron|webview2|browser|headless>
```

| Движок | Описание | Особенности реализации |
|---|---|---|
| `electron` *(по умолчанию)* | Автономное десктопное приложение на базе Chromium и Node.js. | Запускает `apps/ai_assistant/electron/main.js` через локальный бинарник `node_modules/electron/dist/electron.exe`. Поддерживает нативный IPC, горячие клавиши, изоляцию профилей. |
| `webview2` | Легковесное окно Windows на базе встроенного Microsoft Edge WebView2. | Реализовано через библиотеку `pywebview`. Минимальное потребление памяти, поддержка системного трея. |
| `browser` | Открытие вкладки в системном веб-браузере по умолчанию (Chrome, Edge, Firefox). | Открывает канонический URL через системный обработчик `webbrowser.open`. |
| `headless` | Запуск сервера без отображения графических окон. | Выводит URL в консоль. Удобно для интеграции с внешними клиентами, мобильными устройствами в локальной сети или при удалённой отладке. |

## 🔄 Управление портами и процессами (`-c`, `-r`, `--port`)

> [!CAUTION]
> **Регламент безопасности фоновых процессов и ограничение флага `-r`:**
> В системе могут непрерывно работать критичные и длительные задачи:
> - фоновая векторизация и RAG-индексация коммитов и документов;
> - оптическое распознавание (OCR) и парсинг файлов в Paperless-ngx;
> - периодическое фоновое Git-обслуживание (`git gc`, `prune`);
> - мультиагентные пайплайны и потоковые сессии генерации.
>
> **КАТЕГОРИЧЕСКИ ЗАПРЕЩЕНО убивать процессы просто так.**
> Использовать флаг `-r` (`--restart`) разрешается **только с крайней осторожностью** и **строго по явному запросу/подтверждению пользователя**.
>
> Стандартным, безопасным и рекомендованным режимом является флаг **`-c` (`--connect`)**:
> - Если порт свободен — лончер запускает сервер и подключает GUI;
> - Если сервер уже работает — лончер не трогает фоновые процессы, а мгновенно подключает интерфейс к работающему бэкенду.

При разработке и повторных запусках часто возникают ситуации, когда порт сервера (по умолчанию `8002`) уже занят предыдущим экземпляром. Лончер предоставляет гибкие механизмы управления жизненным циклом:

| Параметр | Длинная форма | Значение по умолчанию | Описание |
|---|---|---|---|
| `-c` | `--connect` | `true` *(по умолчанию)* | **Безопасное подключение (Канон):** если сервер на порту уже запущен, лончер не пытается поднять второй бэкенд и не прерывает фоновые задачи, а сразу открывает окно GUI (`--engine`), подключившись к активному инстансу. |
| `-r` | `--restart` | `false` | **ОПАСНО: Принудительный перезапуск:** принудительно завершает (kill) процесс на целевом порту. **Требует явного подтверждения пользователя!** |
| `--port` | `--port <PORT>` | `8002` (или из `config.json`) | Сетевой порт FastAPI сервера. |
| `--host` | `--host <HOST>` | `127.0.0.1` | Сетевой интерфейс для прослушивания соединений. |
| `--no-gui` | — | `false` | Запуск сервера только в консоли без открытия окна интерфейса (аналогично `--engine headless`). |
| `--action` | `--action <ACTION>` | `connect` | Стратегия при обнаружении занятого порта: `connect`, `restart` или `prompt` (интерактивный запрос в терминале). |

### Примеры:

```powershell
# Канонический запуск (безопасное подключение к работающему инстансу + Electron)
.\assist.ps1 -c --engine electron

# Запустить на альтернативном порту 8050
.\assist.ps1 --port 8050 -c --engine electron

# ВНИМАНИЕ: Перезапуск с убийством процесса (ТОЛЬКО по явному согласованию с пользователем!)
.\assist.ps1 -r --engine electron
```

## 📦 Подкоманды CLI

Модуль предоставляет набор консольных утилит для прямой работы с репозиторием, Git-историей и базой знаний.

### 1. `serve` — Запуск сервера и GUI

Явный запуск веб-сервера (полный эквивалент вызова без подкоманды).

```powershell
.\assist.ps1 serve [ПАРАМЕТРЫ]
```

**Доступные параметры:**
- `--port <PORT>` — порт сервера (по умолчанию `8002`).
- `--host <HOST>` — хост сервера (по умолчанию `127.0.0.1`).
- `--engine <ENGINE>` — выбор движка (`electron`, `webview2`, `browser`, `headless`).
- `--no-gui` — запуск без графической оболочки.
- `-c`, `--connect` — подключиться к существующему процессу.
- `-r`, `--restart` — перезапустить процесс на порту.
- `--action <ACTION>` — поведение при занятом порте (`connect`, `restart`, `prompt`).

---

### 2. `status` — Диагностика подсистем

Отображает текущее состояние локального репозитория Git, базы знаний WikiLLM и векторного индекса RAG.

```powershell
.\assist.ps1 status
```

**Пример вывода:**
```text
============================================================
Статус модуля умной истории версий (AI Assistant):
  • Git доступен:        True
  • Текущий HEAD:        a1b2c3d4e5f6
  • База знаний Wiki:    C:\Users\...\data\wiki.db
  • Каталог RAG-индекса: C:\Users\...\data\rag_index
  • Проиндексировано:    342 чанков
============================================================
```

---

### 3. `commits` — История коммитов

Выводит компактный список последних коммитов с хэшем, датой, автором и темой сообщения.

```powershell
.\assist.ps1 commits [--limit N]
```

**Параметры:**
- `--limit <N>` — максимальное число коммитов для отображения (по умолчанию `20`).

**Пример:**
```powershell
.\assist.ps1 commits --limit 5
```

---

### 4. `index` — Индексация коммитов

Запускает инкрементальный процесс анализа изменений: извлекает diff-блоки (`hunks`), связывает их с сущностями WikiLLM и строит эмбеддинги для векторного поиска в RAG.

```powershell
.\assist.ps1 index [--limit N]
```

**Параметры:**
- `--limit <N>` — количество последних коммитов для обработки и индексации (по умолчанию `25`).

**Пример:**
```powershell
.\assist.ps1 index --limit 50
```

---

### 5. `query` — Умный запрос по базе знаний

Выполняет интеллектуальный семантический запрос на естественном языке по истории разработки проекта и выводит структурированный ответ с ссылками на коммиты и подсказками для уточняющих вопросов.

```powershell
.\assist.ps1 query "<ТЕКСТ_ЗАПРОСА>" [--top-k N]
```

**Параметры:**
- `<text>` *(обязательный)* — текст запроса в кавычках.
- `--top-k <N>` — количество наиболее релевантных совпадений из RAG (по умолчанию `5`).

**Примеры:**
```powershell
.\assist.ps1 query "Когда был добавлен адаптер Electron?"
.\assist.ps1 query "Какие файлы менялись при рефакторинге i18n?" --top-k 10
```

## 🐳 Интеграция с Docker и Paperless-ngx

Лончер `assist.ps1` глубоко интегрирован с микросервисом электронного архива документов Paperless-ngx:

1. **Автоматическое определение Docker:**  
   Скрипт проверяет наличие `docker.exe` в `PATH`, а при отсутствии — ищет в стандартном каталоге установки:  
   `C:\Program Files\Docker\Docker\resources\bin`.
2. **Фоновая консоль логов:**  
   Если Docker Desktop запущен, `assist.ps1` поднимает отдельное окно PowerShell под заголовком `Paperless-ngx (Docker)`.
   - Если контейнеры уже работают: подключается к стримингу логов (`docker logs -f --tail 50 <webserver>`).
   - Если контейнеры остановлены: автоматически запускает стек `docker compose up -d webserver` из папки `docker/`.
3. **Отключение консоли логов:**  
   Если стек уже запущен вручную (например, через `docker compose up -d`), используйте параметр `-NoPaperless`:
   ```powershell
   .\assist.ps1 -NoPaperless
   ```

## 🔒 Изоляция данных и директории Chromium

Для соблюдения концепции переносимости (Portable) и защиты системных директорий Windows, все данные браузерных движков изолированы внутри корня проекта:

- **Профиль пользователя (User Data):** `data/chromium/profiles/`
- **Дисковый кэш (Disk Cache):** `data/chromium/cache/`
- **Состояние сессии Electron:** `data/electron_state.json`

> [!IMPORTANT]
> При запуске через `ElectronEngineAdapter` переменная окружения `ELECTRON_RUN_AS_NODE` принудительно очищается. Это исключает конфликт, когда запуск производится из терминала VS Code или Google Antigravity, работающих на собственном рантайме Electron.

## 🔧 Диагностика и устранение неполадок

### 1. Ошибка «Порт 8002 уже занят»
**Штатное безопасное решение:** используйте флаг подключения к работающему инстансу:
```powershell
.\assist.ps1 -c --engine electron
```
Если процесс на порту действительно завис или стал зомби-процессом, **только после подтверждения пользователем** примените принудительный перезапуск:
```powershell
.\assist.ps1 -r --engine electron
```

### 2. Окно Electron закрывается сразу после старта
**Причина:** в окружении осталась переменная `ELECTRON_RUN_AS_NODE=1` или повреждены `node_modules` в `apps/ai_assistant/electron`.  
**Решение:**
1. Запустите интерфейс с выводом консольных логов или в системном браузере:
   ```powershell
   .\assist.ps1 -c --engine browser
   ```
2. Переустановите зависимости Electron:
   ```powershell
   cd apps\ai_assistant\electron
   npm install
   ```

### 3. Docker не найден или выдает предупреждения о томах
Если при старте появляются предупреждения `volume "paperless_pgdata" already exists`:
Это не является критической ошибкой — Docker Compose успешно использует существующие именованные тома. Чтобы логи не мешали в основном окне, запускайте лончер с `-NoPaperless`.
